## 2. Architecture (data flow)

```
System sources (notification listener, media session, battery, telephony, BT)
        ↓
IslandEventEngine          — bounded dual SharedFlow (critical P≥70 / standard), dedupe + coalesce
        ↓
IslandPriorityManager      — preemption/suppression by priority, activeEvent + timeout
        ↓
IslandStateRepository      — IslandMasterState (mode, activeEvent, isDualPill, isMusicPillLeft, …)
        ↓
IslandOverlayView          — Compose dispatch: call → notif → music → battery → system alert → idle
        ↓
IslandOverlayController    — WindowManager sizing/flags via updateWindowLayout(state, prefs)
```

Overlay host: `IslandAccessibilityService` → `TYPE_ACCESSIBILITY_OVERLAY` at Layer 24000 (above StatusBar 22000). Fallback: `IslandOverlayService`.
Idle capsule 124×36dp; enlarged states 200dp / 220dp / 320dp.

Key file map:
- `IslandOverlayView.kt` — compact/expanded dispatch, dual-pill, previews, call end button
- `IslandOverlayController.kt` — window layout, flags, quick-tool actions, message open fallback
- `engine/IslandEventEngine.kt`, `engine/IslandPriorityManager.kt`, `engine/IslandStateRepository.kt`
- `notifications/IslandNotificationListenerService.kt` — notification → event, duplicate-hide cancel
- `notifications/NotificationPermissionManager.kt` — listener permission check + settings intent
- `media/MediaSessionTracker.kt`, `battery/BatteryMonitor.kt`
- `ui/components/` — IslandPreview (live preview), CallCard, NotificationStylePreview, QuickControlsPreview, QuickToolsDrawer, BatteryCompactView, charging/*

## 5. Critical gotcha — notification listener permission

If notifications/music don't appear, check:

```powershell
$adb shell settings get secure enabled_notification_listeners
```

Must contain:
`com.nothing.island.ai/com.nothing.island.ai.notifications.IslandNotificationListenerService`

Enable it (proper way — `settings put` alone doesn't register with the system):
```powershell
$adb shell cmd notification allow_listener com.nothing.island.ai/com.nothing.island.ai.notifications.IslandNotificationListenerService
```

The app Home screen now has a **"Notification access" card with a GRANT button** opening `ACTION_NOTIFICATION_LISTENER_SETTINGS`.

## 7. Platform Limitations & Updated Status (2026-11-25)

1. **Screenshot Gesture (`AccessibilityScreenshotHandler`)** — **Implemented** via `AccessibilityService.performGlobalAction(GLOBAL_ACTION_TAKE_SCREENSHOT)` (API 28+). Platform restriction: fails gracefully if `IslandAccessibilityService` is disabled/unbound.
2. **Bluetooth Earbud Pill (`BluetoothEarbudTracker`)** — **Implemented** for ACL/HFP/A2DP/LE Audio state + HFP battery broadcasts and safe untethered L/R/Case parsing. Platform restriction: requires `BLUETOOTH_CONNECT` on Android 12+ and `BluetoothDevice.getMetadata(METADATA_UNTETHERED_*_BATTERY)` may throw `SecurityException` or return `null` on stock Android without `BLUETOOTH_PRIVILEGED`; unsupported values are shown honestly as `--` rather than faked.
3. **Quick Tools (`QuickToolExecutor`)** — Torch toggles directly via `CameraManager`. Platform restriction: Android 10+ prevents non-system apps from toggling Mobile Data, Wi-Fi, Bluetooth, Location, or Hotspot programmatically; these tiles open system Settings with explicit `↗` affordances, `contentDescription` labels, and tap debouncing.
4. **System Heads-Up Suppression (`SystemNotificationSuppressor`)** — **Hardened** with explicit rules: only clearable, non-ongoing, non-summary, non-call, non-media alerts accepted by Island are cancelled (with loop deduplication). Platform restriction: Android provides no public API for third-party `NotificationListenerService` apps to hide only the heads-up banner without removing/snoozing the shade notification itself.
5. **Dashboard Weather (`WeatherProvider`)** — **Formalized** with explicit `Loading`, `Available`, `PermissionRequired`, `Error`, and `Unavailable` states; defaults to `UnavailableWeatherProvider` ("WEATHER OFF") rather than fabricating weather data.
6. **Release Signing & R8 (`app/build.gradle.kts`)** — Release signing is separated from debug and driven by env vars / `local.properties` (never committed). See `docs/RELEASE_BUILD_CHECKLIST.md`.
